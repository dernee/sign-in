# 班级二维码签到系统（纯前端 · 单机演示版）

一个没有后端、没有数据库的班级扫码签到演示。所有数据只存在于浏览器内存，
刷新即清空。适合课堂演示、课程作业、交互原型验证，**不适合真实考勤**。

- 技术栈：原生 HTML + CSS + JavaScript，无框架、无构建步骤
- 第三方库（CDN）：qrcode.js 生成二维码，SheetJS 解析 Excel
- 入口文件：`index.html`，双击即可运行

---

## 一、快速开始

**方式 A：直接双击 `index.html`**

浏览器以 `file://` 打开即可完成全部流程（导入名单 → 生成二维码 → 打开学生端 → 签到）。
注意：此时二维码内容是本机文件路径，手机扫不出来，只能用页面上的「打开学生端预览」演示。

**方式 B：用本地服务器打开（推荐演示扫码时使用）**

在该目录执行任意一条命令，然后访问 `http://127.0.0.1:8080`：

```bash
python -m http.server 8080
# 或
npx serve -l 8080
```

二维码会指向 `http://127.0.0.1:8080/...`。手机与电脑需在同一局域网时，
把地址换成电脑的局域网 IP（如 `http://192.168.1.20:8080`）再生成二维码，
手机可以打开页面并看到倒计时；但**签到数据仍然无法回传到班长端**——这是纯前端方案的固有限制，不是 bug。

## 三、使用流程

1. 打开 `index.html`，进入班长端。
2. 点击「学生名单」区域，选择 `示例名单.xlsx`（或自备表格）。
   表格需含「学号」「姓名」两列；无表头时默认前两列依次为学号、姓名；支持 `.xlsx / .xls / .csv`。
   导入后页面立即列出全部学生。
3. 点击「生成签到二维码」。二维码内含唯一签到标识（形如 `S-MVP2KCYX-1G8Z`），有效期固定 5 分钟，
   卡片下方有环形倒计时。
4. 点击「打开学生端预览」，在新窗口填写学号与姓名提交；
   或复制链接在浏览器新标签页打开（同浏览器也可通信）。
5. 班长端的「已签到」「未签到」两栏、进度统计实时更新。
6. 5 分钟到期后二维码蒙上「已过期」遮罩；此时学生端只能看到「签到已过期」。

## 四、实现要点

**1. 数据为什么刷新就没了**

`js/store.js` 里的 `state` 是一个闭包内的普通对象，全项目没有任何
`localStorage` / `sessionStorage` / `IndexedDB` / `document.cookie` 写入。
刷新页面时浏览器销毁执行环境，变量随之消失——这就是"刷新即清空"的实现方式，
而不是额外写清理代码。

**2. 二维码为什么刷新就失效**

每次生成二维码都会新建一个会话对象，token 只存在于内存。刷新后内存里没有会话，
学生端发起校验时班长端只能回答 `no-session`，页面据此显示「二维码已失效」。
即便旧链接里的过期时间戳还没到，也照样失效。

**3. 学生端与班长端如何通信**

只有两条同浏览器内的通道，没有网络请求：

| 通道 | 生效场景 |
| --- | --- |
| `BroadcastChannel` | 同一浏览器、同源的任意标签页/窗口（http/https 与 `file://` 实测均可用） |
| `window.postMessage` | 学生端由班长端的 `window.open` 打开时，通过 `window.opener` 直发 |

消息按 `uid` 去重，因此两条通道同时命中也不会重复计一次签到。
1.5 秒内收不到班长端应答，学生端会明确显示「未连接到班长端」，不会假装提交成功。

**4. 时间校验分两层**

- 学生端读 URL 里的 `t`（token）与 `e`（过期时间戳），不依赖网络即可判断"已过期"；
- 班长端在收到提交时用自己内存里的会话重新校验一次，是最终裁决方。

## 五、已知限制（重要）

1. **仅单机演示**：没有服务器，跨设备无法共享数据。手机扫码只能看到页面与倒计时，
   无法把签到写入班长名单。
2. **刷新即丢失**：名单、签到记录、二维码全部清零，且无法导出（没有持久化层）。
3. **不防篡改**：URL 里的过期时间戳由客户端自行读取，改参数即可绕过学生端的时间判断
   （班长端仍会拒绝，但这属于演示级实现，不具备任何安全性）。
4. **依赖 CDN**：断网时 qrcode.js / SheetJS 加载失败，页面顶部会提示「依赖加载失败」，
   导入与生成二维码不可用。
5. **二维码内容是本页 URL**：以 `file://` 打开时，二维码是一个本机文件路径，手机无法识别。
6. **不算考勤凭证**：没有身份认证，理论上任何人只要知道学号和姓名就能代签。

## 六、需求对照

| 需求 | 实现位置 |
| --- | --- |
| URL 参数区分班长/学生模式 | `js/main.js`；`?role=student` 进学生端 |
| 导入 Excel 并展示全部学生 | `js/monitor.js` 的 `parseWorkbook` / `renderAllTable` |
| 生成带唯一标识、5 分钟有效的二维码 | `Store.startSession`、`monitor.js` 的 `drawQr` |
| 刷新即失效、数据清空 | `js/store.js` 全内存实现，无任何持久化 |
| 学生提交并与名单比对 | `Store.submitSignin`（学号不存在/姓名不符/重复签到分别返回） |
| 实时展示已签到、未签到清单 | `monitor.js` 的 `renderLists` |
| 超时提示已过期且不可提交 | `student.js` 的 `boot`/`startClock`；`evalToken` 兜底 |
| CDN + 原生三件套 | `js/vendor.js` + 无框架实现 |
| 限制说明与注释 | 页面顶部提示条、页脚、`index.html` 头部注释、各 JS 文件头注释 |
| 深海波纹 + 毛玻璃 + 响应式 + 弹窗 + 倒计时 | `css/style.css`、`js/ui.js` |

## 七、本地验证记录

在 Edge 156（Chromium 内核，无头模式）中实测：

- `http://127.0.0.1` 场景：37 项断言全部通过，覆盖导入 30 人、二维码绘制、token 格式、
  5 分钟有效期、名单外学号被拒、姓名不匹配被拒、正常签到、重复签到、班长端实时刷新、
  过期链接、刷新后清空、旧二维码失效、无未捕获异常。
- `file://` 场景：11 项断言全部通过，覆盖 CDN 加载、导入、生成二维码、
  `window.open` + `postMessage` 握手、提交回传。
- 核心逻辑单元测试：24 项断言全部通过（token 规则、过期边界、比对结果、Excel 表头识别与
  无表头兜底、重复学号合并）。
